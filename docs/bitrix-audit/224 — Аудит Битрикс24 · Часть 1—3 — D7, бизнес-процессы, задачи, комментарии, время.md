## 1. Architecture & Data Flow

### 1.1 Платформа: как коробка хранит и обновляет данные (D7, `bitrix/modules/main`)

**Схема БД — без единого внешнего ключа.** Три источника DDL сосуществуют:

| Модуль | Источник DDL | Таблиц (скрипт) | FOREIGN KEY |
|---|---|---|---|
| main | `main/install/mysql/install.sql` | 112 | 0 |
| tasks | `tasks/install/db/mysql/install.sql` (+ `install_ft.sql`) | 88 | 0 |
| timeman | `timeman/install/db/mysql/install.sql` + `timeman/install/migrations/tables.php` | 23 + 1 | 0 |
| bizproc | только `bizproc/install/migrations/tables.php` (893 стр., `install/db/*` пусты) | 61 | 0 |
| forum (комментарии задач) | `forum/install/mysql/install.sql` | 27 | 0 |

`grep -ci 'foreign key'` = 0 во всех пяти файлах; в bizproc это задокументировано прямо в билдере:
`// No foreign keys: resource rows are deleted explicitly` (`bizproc/install/migrations/tables.php:846`).
Итог: **целостность целиком на совести PHP-слоя, каскадов нет ни в БД, ни в триггерах** (триггеров тоже 0 —
`grep` по install.sql не находит ни `TRIGGER`, ни `REFERENCES`).

**ORM.** Сущность — `Bitrix\Main\ORM\Entity`; map полей берётся не из DDL-миграции, а из PHP-класса:
`$this->fieldsMap = $className::getMap();` (`main/lib/ORM/Entity.php:232`). Тип поля выводится из
`data_type` → класс `*Field` (`Entity.php:190-191`, неизвестный тип = исключение `Entity.php:204`).
Отдельного DAO нет: SQL собирает `Query` и исполняет коннект — `$connection->query($query)`
(`main/lib/ORM/Query/Query.php:3602`), эскейп через `SqlHelper::forSql` (`main/lib/db/sqlhelper.php:100`).
CRUD-обёртки `EO_*Table` генерируются **`eval`-ом в рантайме** (`main/lib/ORM/Entity.php:988-998`).
Наследие `Bitrix\Main\Entity\*` — ленивые алиасы (`main/include/compatibility.php:43`).
Пример map-класса: `ScriptQueueTable` → таблица `b_bp_script_queue`
(`bizproc/lib/script/entity/scriptqueue.php:25-60`, join-поле `STARTED_USER` как `reference`).

Следствие для проектировщика: **два источника истины о таблице** — DDL в `install/migrations/tables.php`
и map в PHP-классе; синхронизируются вручную, рассинхрон виден только в рантайме.

**Транзакции.** `Application::getConnection()` → пул (`main/lib/Application.php:693-697`), вложенные
транзакции через SAVEPOINT: `if ($this->transactionLevel == 0) START TRANSACTION; else SAVEPOINT TRANS{n}`
(`main/lib/db/mysqlcommonconnection.php:232-243`). Используются точечно — например почтовое событие
`Mail\Event` (`main/lib/Mail/Event.php:100-125`), сохранение записи рабочего времени
(`timeman/lib/service/worktime/worktimeservice.php:362-400`, rollback `:374-406`).

**События — синхронные.** `AddEventHandler()` → `EventManager::addEventHandlerCompatible`
(`main/tools.php:5164-5167`), реестр в таблице `b_module_to_module` (`EventManager.php:190-194`),
кэш реестра в managed-кэше на 3600 с (`EventManager.php:235`). Доставка **инлайново в том же запросе**:
`foreach ($handlers as $handler) $this->sendToEventHandler($handler, $event);` (`EventManager.php:370-376`)
→ `call_user_func_array($callback, $args)`; исключение обработчика гасится только в debug-режиме
(`EventManager.php:461-468`). Обработчики регистрируются исключительно в `install/index.php` модулей —
tasks: 34 `RegisterModuleDependences` + 62 `registerEventHandler` (подсчёт grep по файлу), например
`tasks/install/index.php:82` (forum-комментарии) и `:90` (timeman → стоп таймера).

**Фон — агенты в `b_agent`.** Схема: `b_agent (NEXT_EXEC, DATE_CHECK, AGENT_INTERVAL, IS_PERIOD, RUNNING …)`
(`main/install/mysql/install.sql:342-363`). Агенты выполняются почти при каждом веб-запросе: после отправки
ответа `Application::terminate()` гонит фоновые джобы — `addBackgroundJob(['CAgent','CheckAgents'],…,JOB_PRIORITY_LOW)`
(`main/lib/Application.php:177-180`, запуск `:429-443`), плюс внешний cron `bitrix/php_interface/cron_events.php:14-17`.
Изоляция: `LOCK_TIME = 600` (`classes/general/agent.php:16`), захват строки `UPD​ATE b_agent SET DATE_CHECK=…+600`
(`agent.php:463`), стоп за 30 с до лимита (`agent.php:477-480`), лимиты 100/1000 за прогон (`agent.php:447`).
**Исполнение агента — `eval` строки NAME**: `$eval_result = … eval("$eval_result=".$arAgent["NAME"])`
(`agent.php:507-508`).

**Кэш.** Движки объявлены в `.settings.php` и выбираются в `Data\Cache` (`main/lib/Data/Cache.php:54-107`:
redis/memcached/apcu/files, иначе `CacheEngineNone`). Managed-кэш сбрасывается один раз в конце запроса —
`finalize()` (`ManagedCache.php:197-199`, `Application.php:439`). Теговый кэш лежит в БД: `b_cache_tag`
(`install.sql:870-881`, `Data/TaggedCache.php:130-170`). ORM-кэш включается per-table опциями `cache.ttl`
(`ORM/Data/DataManager.php:421-423`), TTL зажимается конфигом `cache_flags` (`Entity.php:1382-1399`).

**Очереди.** Коробка не имеет `b_notify`/`b_webhook` (grep = 0); вместо этого:
шина сообщений `b_main_messenger_message` (`main/lib/Messenger/Internals/Storage/Db/Model/MessengerMessageTable.php:54`,
брoker `get/send/ack` — `Messenger/Broker/BrokerInterface.php:28-55`), почтовая очередь `b_event`
(`Mail/EventManager.php:57`, чистка `:148-165`), и устойчивый паттерн **«таблица-очередь + агент/степпер»**:
`b_bp_script_queue` (`bizproc/install/migrations/tables.php:269`), `b_ai_queue` (`ai/…/tables.php:5`),
`b_crm_webform_queue` (`crm/…/tables.php:1737`). Общий механизм отложенной работы —
`Application::addBackgroundJob()` (`Application.php:886-895`).

**Права доступа не встроены в ORM.** `DataManager::setDefaultScope($query) { return $query; }`
(`main/lib/ORM/Data/DataManager.php:304-307`) — заглушка, которую модули переопределяют точечно
(например `iblock/.../commonelementtable.php:43-46` накладывает фильтр по IBLOCK_ID, не права).
Права — отдельные явные чекеры (`CUser::IsAdmin` — `classes/general/user.php:3331`;
`b_user_group`/`b_user_access` — `install.sql:272,965`; пример чекера —
`rest/lib/Internal/Access/WebhookAccessChecker.php:21-24`). **Фильтрация списка = opt-in**: забыл вызвать —
получил чужие строки.

**REST.** Вход `/rest/` → `bitrix/services/rest/index.php` → `bitrix:rest.provider` → `bitrix:rest.server` →
`CRestServer` (`rest/classes/general/rest.php:40,119`), auth через событие `OnRestCheckAuth`
(`rest_util.php:544-551`), входящие вебхуки хранятся как пароли приложения в `b_rest_ap`
(`rest/lib/apauth/password.php:52-71`). Новая ветка REST 3.0 (`CRestApiServer`, V3-контроллеры модулей
по конфигу `rest.defaultNamespace` из `.settings.php`) обслуживает **другой сегмент URL — `/rest/api/…`**
(проверено вживую, §4.4): на классическом `/rest/` методы V3 возвращают `ERROR_METHOD_NOT_FOUND`.
