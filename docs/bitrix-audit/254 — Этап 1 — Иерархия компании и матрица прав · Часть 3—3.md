### 5.2. Схема базы данных: политики и materialized ACL

```sql
-- ============ POLICY (policy_service) ============
CREATE TABLE rbac_role (
    id      BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    code    TEXT NOT NULL UNIQUE,
    name    TEXT NOT NULL,
    is_system BOOLEAN NOT NULL DEFAULT FALSE
);

-- субъект = структурный код, как в Bitrix, но нормализованный
CREATE TABLE subject_code (
    id        BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind      TEXT NOT NULL,          -- 'USER' | 'NODE' | 'NODE_SUBTREE' | 'TEAM' | 'GROUP'
    ref_id    BIGINT NOT NULL,
    UNIQUE (kind, ref_id)
);
CREATE TABLE rbac_role_subject (
    role_id BIGINT NOT NULL REFERENCES rbac_role(id) ON DELETE CASCADE,
    subject_id BIGINT NOT NULL REFERENCES subject_code(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, subject_id)
);

-- одно правило = одна строка (модель b_crm_role_perms, но типизированная)
CREATE TABLE policy_rule (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    role_id     BIGINT NOT NULL REFERENCES rbac_role(id) ON DELETE CASCADE,
    entity_type TEXT   NOT NULL,        -- 'deal','lead','smart:<id>'
    operation   TEXT   NOT NULL,        -- 'read','write','delete','export','transition'
    scope_field TEXT,                   -- NULL | 'stage' | 'category' | 'owner'
    scope_value TEXT,                   -- 'C3:PREPAYMENT' | '*' | NULL
    effect      SMALLINT NOT NULL DEFAULT 1,   -- 1 allow, -1 deny
    condition   JSONB,                  -- ABAC: {"attr":"owner_dept","op":"subtree_of","subject":"self"}
    UNIQUE (role_id, entity_type, operation, scope_field, scope_value)
);
CREATE INDEX policy_rule_lookup_idx ON policy_rule (entity_type, operation) WHERE effect = 1;

-- ============ ACL INDEX (projector, не источник истины) ============
-- партиционирование по entity_type: каждая партиция со своими индексами
CREATE TABLE acl_item (
    entity_type  TEXT   NOT NULL,
    entity_id    BIGINT NOT NULL,
    owner_id     BIGINT NOT NULL,
    category_id  INT    NOT NULL DEFAULT 0,
    step         TEXT   NOT NULL DEFAULT '',      -- стадия/прогресс
    is_opened    BOOLEAN NOT NULL DEFAULT FALSE,
    is_always_readable BOOLEAN NOT NULL DEFAULT FALSE,
    observers    BIGINT[] NOT NULL DEFAULT '{}',
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (entity_type, entity_id)
) PARTITION BY LIST (entity_type);

CREATE TABLE acl_item_deal   PARTITION OF acl_item FOR VALUES IN ('deal');
CREATE TABLE acl_item_lead   PARTITION OF acl_item FOR VALUES IN ('lead');
CREATE TABLE acl_item_contact PARTITION OF acl_item FOR VALUES IN ('contact');

CREATE INDEX acl_item_owner_idx  ON acl_item_deal (owner_id, entity_id);
CREATE INDEX acl_item_open_idx   ON acl_item_deal (entity_id) WHERE is_opened;
CREATE INDEX acl_item_cat_idx    ON acl_item_deal (category_id, owner_id, entity_id);
CREATE INDEX acl_item_obs_idx    ON acl_item_deal USING GIN (observers);
```

Единственный источник истины — `policy_rule` + оргструктура; `acl_item` — **read-model**, который
перестраивается событием (`entity.updated` → projector) и всегда может быть пересобран заново.

Генерация ограничения выборки (эквивалент `QueryBuilder::build()`):

```go
type Grant struct { Owners []int64; Cats []int32; Steps []string; Opened, ReadAll bool }

func (s *QueryGuard) Restrict(ctx context.Context, q *orm.Query, sub Subject, et string, op Op) error {
    g, err := s.policy.Decide(ctx, sub, et, op)      // кэш в Redis, TTL 60s
    if err != nil { return err }                     // ошибка политики = отказ, не пропуск
    switch g.Effect {
    case EffectAll:  return nil
    case EffectNone: q.WhereRaw("FALSE")
    default:
        // один JOIN на партицию + 2–3 IN, как в Bitrix, но с параметрами
        q.Join("acl_item a ON a.entity_type = ? AND a.entity_id = e.id", et).
          WhereRaw(`(a.owner_id = ANY(?) OR ? AND a.is_opened OR a.observers && ?)
                     AND a.category_id = ANY(?) AND a.step = ANY(?)`,
                   g.Owners, g.Opened, sub.Principals, g.Cats, g.Steps)
    }
    return nil
}
```

**Никаких прав на уровне контроллера** — guard вызывается из repository; `SELECT` без него компилируется
с запретом (lint-правило / code-owner check).

### 5.3. Схема фоновых воркеров

| Процесс | Технология | Что делает | Гарантии |
|---|---|---|---|
| `acl-projector` | **Debezium → Kafka → Go consumer** (или `LISTEN/NOTIFY` + outbox) | `entity.updated` → upsert `acl_item`; `membership.changed` → инвалидация кэша ролей | at-least-once + идемпотентный upsert (`ON CONFLICT`), порядок по ключу сущности |
| `policy-cache-refresher` | Go worker, 30 c | прогрев `policy decisions` в Redis, инвалидация по `role.updated` | TTL 60 c, версия политики в ключе (`policy:v{N}`) |
| `org-reindex` | Postgres `trigger` → `pg_notify` → worker | пересчёт `path`/`org_node_closure` при перемещении узла | транзакция с изменением узла; тяжёлые массовые переносы — отдельная job с `depth`-курсором (паттерн `NodePathTable::recalculate`) |
| `subject-code-maintainer` | CDC на `org_member` | пересчёт `subject_code('NODE_SUBTREE', node)` при изменении дерева | инкремент, не полный пересчёт |
| `acl-backfill` | временная job (pat-терн `ReFillDynamicTypeAttr`) | курсор по `id`, чанки, прогресс в таблице `job_progress`, переключатель `read_path=v1|v2` | dual-write на время переключения |
| `audit-writer` | Kafka → ClickHouse/PG | журнал изменений прав (`role`,`grant`,`deny`) | append-only, ретеншн |

Для очереди «кто-то кому-то перезвонит/согласует» — **BullMQ/Temporal** не нужен на старте: Postgres
`SKIP LOCKED` + таблица задач покрывает корпоративный масштаб; Kafka — только для потока событий CDC.

### 5.4. Контракты API

**REST (управление):**
```
GET    /api/v1/org/structures/{id}/nodes?parent_id=&depth=      → дерево (курсорная пагинация)
POST   /api/v1/org/nodes/{id}/members        {user_id, role}
GET    /api/v1/org/nodes/{id}/subordinates?recursive=true&depth=3
POST   /api/v1/roles                        {code, name}
PUT    /api/v1/roles/{id}/rules             {rules:[{entity_type,operation,scope_field,scope_value,effect,condition}]}
POST   /api/v1/roles/{id}/subjects          [{kind,ref_id}]
GET    /api/v1/policy/decision?subject=&entity_type=&entity_id=&op=   → {effect, reason, policy_version}
POST   /api/v1/policy/decision/batch        → [{entity_id, effect}]
GET    /api/v1/audit/permissions?role_id=&since=
```

**gRPC (внутреннее, для query-guard в каждом сервисе):**
```proto
service Policy {
  rpc Decide(DecideRequest) returns (Decision);            // up to 1 rps на сущность
  rpc DecideBatch(repeated DecideRequest) returns (DecisionSet);
  rpc Invalidate(InvalidateRequest) returns (Empty);       // role.updated / membership.changed
}
message DecideRequest { string subject_id; string entity_type; int64 entity_id; string operation; }
message Decision      { Effect effect; int64 policy_version; repeated string reason_codes; }
```

**WebSocket:** права не шлются как «сырой список» — только события инвалидации:
```json
{"type":"policy.invalidated","version":42,"reason":"role.updated","role_id":7}
{"type":"acl.changed","entity_type":"deal","entity_id":1234,"visible":false}
```
Клиент перезапрашивает `GET /policy/decision/batch` по открытому экрану (паттерн Bitrix: права в
запросе считаются заново, а не кэшируются в браузере на долго).

### 5.5. Матрица Open Source вместо велосипедов Битрикса

| Велосипед Bitrix | Замена | Почему |
|---|---|---|
| `b_crm_role_perms` + ручной `PermissionsManager` | **OpenFGA** (tuple-based) или **AWS Cedar** или **Casbin** | готовая семантика `user:viewer#member@folder`, объяснение отказа, версионирование политик |
| свой парсер кодов `AccessCode` | **Zanzibar/OpenFGA relationships** + `ltree` для иерархии | `node:7#child@node:3` вместо строк `SND7` |
| closure table со своим `recalculate()` | **PostgreSQL `ltree`** (+ опционально closure) | операторы `@>`, `nlevel`, индекс GIST из коробки |
| `b_crm_access_attr_*` (6 таблиц × 9 индексов) | **одна `acl_item` c LIST-партиционированием** + GIN на `observers` | схема одна, партиции по типу |
| `CMain::GetUserRight` + `b_module_group` | тот же OpenFGA/Cedar namespace `module:X#access` | единая точка принятия решений |
| `CAccess::UpdateCodes` + кэш 100 дней | **subject snapshot в Redis, версионированный** (`subject:v{N}`) | отзыв прав — инвалидация по событию, TTL ≤ 60 c |
| `CPHPCache` для дерева | **Redis + materialized view** (`org_node_path_mv` REFRESH MATERIALIZED VIEW CONCURRENTLY) | читается несколькими узлами, не «замерзает» на 30 дней |
| `CAgent` (cron-планировщик в БД) | **Temporal** (или `river`/`pg_cron` на старте) | ретраи, идемпотентность, визуальный прогресс бэкфилла |
| `PermissionToken` без TTL | **JWT с `exp`+`jti`** (`golang-jwt`) или короткоживущий opaque token в Redis | отзыв и ограничение времени жизни |
| ручной raw SQL в репозиториях | **sqlc / squirrel / GORM с parameterization** + `goose` миграции | компиляторная проверка запросов, никакой конкатенации |
| события в БД + `GetModuleEvents` | **outbox + Kafka/Redpanda**, схема Avro/Protobuf | потребители не теряют события, есть replay |
| аудит прав в `getLogger('Permissions')` | **append-only audit log** (ClickHouse) + `policy_version` в каждой строке | кто и на каком основании выдал доступ |

### 5.6. Чек-лист при переносе (чтобы не повторить ошибки этапа)

1. Один источник истины на дерево; read-model строится из него, а не живёт параллельно.
2. Права проверяются в репозитории; обход невозможен (архитектурное ограничение, не соглашение).
3. Никаких побочных эффектов в чтении (ни записи, ни планирования агентов).
4. Кэш политики — версионированный, TTL ≤ 60 с, инвалидация по событию; никогда «100 дней».
5. Materialized ACL пересобираем полностью; расхождение обнаруживается nightly-reconciler'ом.
6. Все write-операции по ролям — в одной транзакции (`DELETE … + INSERT` атомарно).
7. Валидация словаря прав — по реестру, все элементы массива, а не первый.
8. Токены — с `exp` и `jti`; никаких «вечных» подписанных ссылок.
9. Каждая таблица-иерархия и каждая ACL-таблица имеют FK и каскад; осиротевание невозможно.
10. Метрики: `policy_decide_duration`, `acl_stale_events`, `deny_by_reason` — иначе отказы не диагностируются.
