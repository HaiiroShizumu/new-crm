**Контракт «фабрики типов»**: `Factory::getFieldsMap()` переводит *общие* имена полей
(`Item::FIELD_NAME_*`) в *специфичные* для сущности (`STAGE_ID` ↔ `STATUS_ID` и т.п.),
а `DisabledField` отключает поля, которые сущность не поддерживает
(`getItemByEntityObject()` помечает `CATEGORY_ID`/`STAGE_ID` как disabled, если соответствующий
capability выключен). Это позволяет одному `Item`-классу обслуживать 40+ типов сущностей.

### 1.3. Жизненный цикл сохранения сущности (горячий путь)

```
HTTP POST /crm/deal/... (или REST, или autorun-контроллер)
 └─ Controller\Autorun\{setstage,assign,setcategory,setopened,delete,observers}
      └─ (new TransactionWrapper($operation))->launch()        ← НОВЫЙ путь, с транзакцией
           ├─ operation->disableBizProc()->disableAutomation()
           ├─ BEGIN
           │   └─ Operation::launch()                          [Operation.php:128–280]
           │        ├─ $this->item->fill()                    (перечитать текущее состояние)
           │        ├─ preSaveChecks(): checkAccess + checkFields
           │        ├─ $this->itemBeforeSave = clone $this->item
           │        ├─ save() → Item::save() → entityObject->save() + implementations
           │        ├─ processFieldsAfterSave()
           │        ├─ updatePermissions()   → Controller::register() → b_crm_access_attr_*
           │        ├─ updateSearchIndexes() → SEARCH_CONTENT
           │        ├─ updateDuplicates()    → integrity/* (авто-дедупликация)
           │        ├─ updateCounters(), clearItemCategoryCache(), clearItemStageCache()
           │        ├─ autocompleteActivities(), registerStatistics()
           │        ├─ saveToHistory()       → *_stage_history
           │        ├─ createTimelineRecord()→ b_crm_timeline
           │        ├─ processActions(AFTER_SAVE)
           │        └─ createToDoActivity(), preparePullEvent(), sendPullEvent()
           ├─ COMMIT (или ROLLBACK)
           ├─ runBizProc()     — после коммита
           └─ runAutomation()  — после коммита
```

Классический (не-autorun) путь `Factory::getUpdateOperation(...)->launch()` идёт **без транзакции**:
`TransactionWrapper` применяется только в `lib/controller/autorun/*` (setstage, assign, setcategory,
setopened, observers, delete). Ошибки bizproc/automation в `Operation::launch()` **проглатываются** —
закомментированный код:

```php
$bizprocResult = $this->runBizProc();
// if (!$bizprocResult->isSuccess()) { $result->addErrors($bizprocResult->getErrors()); }
```

### 1.6. Выборка списка с правами и «двухфазный» фетч

```php
// Service\Factory::getItems()   [Factory.php:420–466]
$itemIds = $this->getDataClass()::getList(['select' => ['ID']] + $parameters)   // фаза 1: id под правами
                ->fetchCollection()->getIdList();
$params  = ['filter' => ['@ID' => $itemIds], 'limit' => null] + $parameters;
unset($params['runtime']['permissions']);                                       // фаза 2: JOIN прав снят
$list = $this->getDataClass()::getList($params);                                // fetch по явному списку id
```
Фаза 1 оставляет runtime-поле `permissions` (INNER JOIN ACL) → список id уже отфильтрован;
фаза 2 снимает JOIN, чтобы не плодить дубли строк от join'ов. Обход двух фаз —
`isSkipSelectIdsHack()` (когда фильтр содержит строгий `=ID`).

## 2. Удачные решения (What to Keep / Patterns to Adopt)

### 2.1. Container + Factory: один полиморфный вход на 40+ типов
`Container::getFactory(entityTypeId)` возвращает объект с единым контрактом
(`getItems/getStages/getCategories/getAddOperation/getFieldsCollection/is*Enabled`).
Логика «сделка vs контакт vs смарт-процесс» инкапсулирована в наследниках, а вызывающий код
(списки, канбан, таймлайн, права, REST) не содержит `if type == DEAL`.

```text
factory = container.factory(entity_type_id)
op      = factory.update_operation(item, context)
result  = op.launch()      // единый pipeline независимо от типа
```
**Переносим как есть**: порт `EntityGateway` в hexagonal-архитектуре + `registry[entity_type] → handler`.
