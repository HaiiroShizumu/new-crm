## 1. Провайдеры монтирования и `currentWorkspace` (условие В1.2)

Дерево на базе `twenty/v2.45.6` (чтение):

```
index.tsx:13            root.render(<App />)
└ App.tsx:24            <JotaiProvider store={jotaiStore}>   ← ВНЕШНИЙ провайдер jotai
  … AppErrorBoundary → I18nActivationGate → I18nProvider →
    LocaleDirectionProvider → ToastProvider → IconsProvider →
    ExceptionHandlerProvider → HelmetProvider → ClickOutsideListenerContext
    └ DomainShell.tsx:24        <SharedAppProviders>
      └ SharedAppProviders.tsx:14   <ApolloProvider>
        └ <BaseThemeProvider>       ← тут лежат ClientConfigProviderEffect,
          └ <ThemeProvider>            PendingServerSignOutEffect, <SmbSkinEntry/> (P-013)
            └ ClientConfigProvider → children
```

- **Где монтировать:** внутри `SharedAppProviders` как сосед `ClientConfigProviderEffect` — то есть **ребёнком `BaseThemeProvider`**. Это ровно то, чего требует сам эффект: комментарий в `SmbSkinProviderEffect.tsx:59-60` — *«Layout effect so the skin attributes land **before the parent ThemeProvider** snapshots computed CSS variables into its JS theme on mount»*; layout-effect ребёнка в React отрабатывает раньше layout-effectа родителя.
- **Почему не `index.tsx`:** `JotaiProvider` живёт в `App.tsx:24`, то есть **снаружи `<App />` jotai-атомов не существует**. А эффект читает 6 атомов через `useAtomStateValue` (`SmbSkinProviderEffect.tsx:40-45`).
- **Источник `currentWorkspace`:** `currentWorkspaceState` — **jotai-атом**, `packages/twenty-front/src/modules/auth/states/currentWorkspaceState.ts:56` (`createAtomState`, localStorage). Скин читает смежный `currentWorkspaceMemberState` (`SmbTopBarCurrentUser.tsx:27`). Оба доступны только внутри `JotaiProvider`.
- **`mode` для эффекта:** в v2.45.6 есть только `ThemeSchemeContext` (setter), готового `useTheme`-хука с режимом нет. Поэтому режим считается в нашем `SmbSkinEntry` той же формулой, что и `BaseThemeProvider.tsx:31-34` (`persistedColorSchemeState` + `useSystemColorScheme` → `'dark' | 'light'`), — **без правки `BaseThemeProvider`**. Дублируется одна строка логики ради отсутствия второй правки ядра.
- **Второй файл:** нужен → **`P-013`** (импорт + `<SmbSkinEntry />`), запись в `docs/PATCHES.md`, риск конфликта «средний» (вложенность провайдеров меняется upstream).

### 3.2 Острова: 12 файлов не переносились

Зависимость от 14 дырок нашлась ровно в **12 файлах** (из 95), и они образуют замкнутые острова — **обратных ссылок из остальных 80 файлов: 0**:

## 5. CI (условие В1.3)

В `.github/workflows/fork-ci.yaml`, job `typecheck`, шаг после основного `tsgo`:

- запускает `nx run twenty-front:typecheck --skip-nx-cache`, пишет вывод в лог;
- отсчитывает ошибки с маской `src/modules/smb-(skin|brand)/`;
- **всегда** (`if: always()`) кладёт их в Step Summary — падение основного типчека не маскирует картину по скину;
- `exit 1` **только** если ломано внутри скина — это и есть «явный вердикт после обновления upstream»: отличает «upstream изменил сущность, на которую ссылается скин» от «сломано ядро».

Валидация: `ruby -ryaml` → `yaml OK`, шаги job'а = Checkout, Install, Build twenty-shared, Typecheck, **Типы скина**.

## 8. Расхождения с ADR / планом

1. **План v3 называл `packages/smb-brand`** (то есть M1) в Этапе 2 — но критерий самого плана («выбирается ОДНИМ решением … по измерению») привёл к M2: M1 = 5–7 правок существующих файлов + **подтверждённый цикл** (скин импортирует 128 `@/*` внутренностей twenty-front, а twenty-front должен зависеть от `smb-front` → границы Nx), M2 = 1 правимый файл ядра + 0 циклов. Решение принято владельцем в clarify; `smb-brand` живёт как каталог, а не пакет.
2. **ADR-007 в части фронта переписан** по условию В1.4 — статус ADR остаётся «Предложено» (утверждение на гейте 0.5), но фронтовая часть теперь описывает свершившийся факт, а не проект.
3. **Одна строка против двух в `index.tsx`** — условие «шов = одна строка» выполнено через `@import` в `smb-skin.css` (records и бренд въезжают оттуда). Побочный эффект: `@import messenger` пришлось закомментировать (файл не переносился) — при Этапе 4 строка возвращается.
4. **«Прослойка `upstream.ts`» — рассмотрено, рекомендую отложить.** Идея: все наружные импорты скина идут через один модуль, и merge upstream правит один файл вместо 82. Оценка: 128 реэкспортов, из них типы требуют `export type {…}`; выигрыш проявится только на первом реальном обновлении upstream. Критерий принятия: посчитать на первом merge, сколько из 128 импортов реально задели — если >5, плодить прослойку; иначе это накладные расходы на каждый импорт и на автоподстановку IDE. **Не реализовано, вопрос в разделе 10.**
5. **В `OURS` паттерн с `[a-z0-9-]`** не покрывает подчёркивания (например, `smb_brand`); текущие каталоги (`smb-skin`, `smb-brand`) покрываются. Если понадобится имя с `_` — паттерн правится отдельным коммитом гейта.
