# R12 — канал Б24 и документооборот: архитектура и основа (2026-10-13)

> Перенесено 2026-10-13 из клона `twenty-rebuild` (отчёт `docs/reports/R13.md`). Номера ADR, реестра и
> отчётов и пути каталогов приведены к этому дереву; содержание решений не менялось.

Ветка `chore/docs-and-tooling`, не закоммичено. Вход: запрос владельца от 2026-10-13 (приложение
«Документооборот» в маркетплейсе Б24: одна ссылка на все порталы, вход без пароля, авторегистрация
сотрудников, вкладки «Задания», «Процессы», «Документы»; сложное сделать, рутину отдать Hermes).

Решения: `docs/adr/ADR-015-bitrix-channel.md`, `docs/adr/ADR-016-docflow.md`.
Очередь для Hermes: `docs/TODO-docflow.md`.

## Сделано

**Сервер, модуль `modules/smb-bitrix` (подключён в `SmbServerModule`):**

- три адреса: `POST /webhooks/smb-bitrix/install`, `/app`, `/event`;
- проверка каждого запроса обменом refresh-токена на oauth.bitrix.info (тело запроса не
  считается доверенным, портал и адрес REST берутся из ответа Б24);
- таблицы `smbBitrixPortal`, `smbBitrixUser` и миграция; токены портала шифруются;
- создание аккаунтов сотрудников: при установке (фоном, все активные) и при первом открытии;
  правило безопасной привязки существующего аккаунта по email;
- вход: штатный login-token и редирект на `/verify?…&returnToPath=/docflow`;
- ссылка «Открыть CRM» (мутация `createSmbBitrixCrmLink`): установка пароля, если его нет;
- создание workspace при установке за флагом `SMB_BITRIX_AUTO_PROVISION_WORKSPACE` (по умолчанию
  выключено), удаление приложения по `application_token`;
- ограничение частоты по IP на каждый адрес.

**Фронт:**

- `modules/smb-embed`: определение фрейма, cookie для фрейма, загрузка `BX24`, кнопки «На весь
  экран» и «Открыть CRM»;
- `modules/smb-docflow` и страница `/docflow/:tab?`: три вкладки; «Задания» (мои и остальные,
  форма задания справа), «Процессы» (список запускаемых, запуск с параметрами), «Документы»
  (заглушка до приложения с объектами);
- логика: стартовая форма как параметры процесса, обязательные поля, исполнитель и срок шага
  через `settings` поля, разрешение переменных исполнителя из состояния запуска.

**Правки ядра:** P-031…P-031 новые, P-018/P-019/P-020 дополнены. 96 новых файлов в наших каталогах.

## NOT RUN

| Что | Почему |
|---|---|
| `nx build twenty-shared`, полный `tsgo` фронта и сервера | swap 79–89% за сеанс, порог правила 80% |
| Запуск сервера, проверка DI модуля `SmbBitrixModule` | то же; БД на машине занята другим агентом |
| Миграция на реальной БД, `database:migrate:generate` | то же. Миграция написана вручную |
| Любой запрос к oauth.bitrix.info или порталу | нет тестового портала и `client_id`/`client_secret` |
| Страница `/docflow` в браузере, вёрстка, кнопки во фрейме | dev-стек не поднимался |
| Запуск процесса с параметрами от начала до конца | нужен работающий сервер с worker |
| Cookie во фрейме в Chrome, Safari, Firefox | нужен портал |

Итого: логика покрыта модульными тестами и точечной проверкой типов. Ни одна строка не
выполнялась в работающем приложении. До прогона A1–A6 из `docs/TODO-docflow.md` считать код
непроверенным.

## Расхождения и находки

- Токены сессии фронт хранит в cookie с `SameSite=Lax` (`utils/cookie-storage.ts`). Во фрейме
  чужого сайта они не сохраняются, поэтому вход из Б24 без правки P-032 не работал бы вообще.
  В S6 и AUDIT-goals это значилось как «риск, проверить», фактически это была гарантированная поломка.
- `AuthModule` не экспортирует `SignInUpService` и `ResetPasswordService`, отсюда P-031.
- Шаг-форма не разрешает переменные в значениях полей (`form.workflow-action.ts` передаёт поля как
  есть). Исполнитель-переменная разрешается на клиенте.
- Схема поля формы допускает произвольный `settings`, это и позволило обойтись без правок ядра
  для обязательности и исполнителя.
- В v2.45.6 под флагом `IS_WORKFLOW_CORE_INDEX_PAGE_ENABLED` workflow переезжает в «core».
  Документооборот читает объекты workspace и с этим флагом работать не будет.
- ADR-010 (поправка 2026-10-13) ссылается на `docs/reports/R06.md`, файла в каталоге нет.
- Старый код канала (`company-tunnel`) не переносился: модель доказательства запроса другая.

## Вопросы владельцу

1. Есть ли тиражное приложение в кабинете вендора Б24 (`client_id`, `client_secret`) и тестовый
   портал? Без них канал не проверить.
2. Создание workspace при установке: включаем флаг или оператор привязывает порталы вручную, пока
   не решены лимит 5 workspace и wildcard-сертификат?
3. Аккаунты из Б24 создаются с подтверждённым email без письма (ADR-015 п.5). Подтвердить.
4. Сотрудник, чей email уже занят аккаунтом в другой компании, сам не войдёт (ADR-015 п.4).
   Устраивает ручная привязка администратором?
5. Обязательность полей сейчас проверяет только наш интерфейс. Серверную проверку делать сразу
   или после проверки на стенде?
6. Доступ к заданиям: все, у кого есть право читать запуски процессов, видят все задания. Права
   «только свои» это Enterprise-функция. Оставляем так до ответа юриста?
