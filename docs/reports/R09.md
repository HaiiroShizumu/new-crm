## Расхождения / допущения

1. Самореференсные связи (`department→department`, `workspaceMember→workspaceMember`) в примерах SDK не встречаются — написаны по образцу пары «человек ↔ открытка». Если метаданные их не принимают, придётся заменить `manager`/`parentDepartment` на связь через промежуточное поле — выяснит S1.
2. Имя поля должности — `jobTitle`, а не `position`: `position` занято системным полем записи.
3. `updateMany` с `parentDepartmentId` запрещён целиком. Если встроенные операции UI используют `updateMany` для переноса — смягчить (проверять поштучно по `filter`).
4. Страница использует `useFindManyRecords` с `recordGqlFields` вида `departmentId`/`managerId`; допустимость этих имён в GraphQL-поле проверить на стенде.
5. Права: перенос сотрудника обновляет `workspaceMember` — право на это определяет роль пользователя; обычный сотрудник, скорее всего, перенести не сможет (это желаемо, но не проверено).
