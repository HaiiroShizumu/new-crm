## Сделано

Запросы `POST /webhooks/smb-bitrix/{app,install}` в двух режимах окружения.
Режим «с настройми» — сервер перезапущен с `SMB_BITRIX_CLIENT_ID=test-client
SMB_BITRIX_CLIENT_SECRET=test-secret`, затем восстановлен без них.

| Режим | Запрос | Статус | Страница | Location |
|---|---|---|---|---|
| без `SMB_BITRIX_*` | `/app` `-d 'member_id=x'` | **403** | HTML | нет |
| без `SMB_BITRIX_*` | `/app` `--data 'refresh_token=x'` | **503** | HTML | нет |
| без `SMB_BITRIX_*` | `/install` `-d 'member_id=x'` | **403** | HTML | нет |
| с `SMB_BITRIX_*` | `/app` `-d 'member_id=x'` | **403** | HTML | нет |
| с `SMB_BITRIX_*` | `/app` `--data 'refresh_token=x'` | **403** | HTML | нет |
| с `SMB_BITRIX_*` | `/install` `-d 'member_id=x'` | **403** | HTML | нет |
| с `SMB_BITRIX_*` | `/install` `--data 'refresh_token=x'` | **403** | HTML | нет |

## Подтверждено (вывод команд)

- Ни в одном ответе нет заголовка `Location` — «в обоих случаях в ответе нет
  заголовка `Location`» из A4 выполнено.
- Каждый отказ отвечает HTML-страницей (`Content-Type: text/html`, см.
  `render-smb-bitrix-page.util.ts`).
- Лог сервера называет коды ошибок: без настроек и `refresh_token=x` →
  `NOT_CONFIGURED: SMB_BITRIX_CLIENT_ID and SMB_BITRIX_CLIENT_SECRET are not set`
  (→ 503); без `refresh_token` → `INVALID_REQUEST: Request has no refresh token`
  (→ 403); с настройми и фиктивным refresh-токеном →
  `PORTAL_PROOF_FAILED: Refresh token was not accepted (HTTP 200)` от
  `oauth.bitrix.info` (→ 403).
- Сообщение «This page must be opened from Bitrix24» соответствует коду
  `INVALID_REQUEST` (`smb-bitrix.exception.ts:27`); в HTML оно приходит
  идентификатором `fT0E15` (каталоги переводов не пересобраны — см. R13).

## Расхождения

- A4 ждёт **503** на `/app` `-d 'member_id=x'` без `SMB_BITRIX_*` — получено
  **403**. Причина в порядке проверок: `proveRequest` сначала требует
  `refresh_token` (`INVALID_REQUEST` → 403), и только при его наличии
  `oauthService.exchangeRefreshToken` доходит до проверки конфигурации
  (`NOT_CONFIGURED` → 503). Тот же запрос с `refresh_token=x` без настроек даёт
  ожидаемый 503. Поведение не менялось — какое из двух задумано, решает владелец
  (совпадает с «Расхождения» из R13, там же).
