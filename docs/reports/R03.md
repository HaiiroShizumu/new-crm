## А. Подтверждено

### A1. Универсальное правило гейта

Регулярки `OURS`/`CORE_IN_OURS` заменены статус-правилом; `CORE_IN_OURS` удалён.

```bash
# источник пар «статус<TAB>путь»
git_pairs() {
  if [ "$STAGED" = true ]; then
    git -c core.quotepath=false diff --cached --name-status --no-renames "$BASE"   # BASE -> ИНДЕКС
  else
    git -c core.quotepath=false diff --name-status --no-renames "$BASE" HEAD       # BASE -> HEAD
  fi
}
# требует записи, если:  статус != A   ИЛИ   (статус == A  И  путь ВНЕ OURS)
OURS='(^|/)locales/(generated/|.*\.po$)|^(packages/smb-|apps/|docs/|scripts/|smb/|\.claude/|\.cursor/|\.github/workflows/fork-)'
```

Ключевые решения:

- **`--staged` теперь сравнивает `$BASE..индекс`, а не `HEAD..индекс`.** Без этого любой **уже закоммиченный наш** файл при правке читался как `M` и ложно требовал записи (первый прогон тестов: 6 из 12 падали именно на этом).
- **`OURS` сужен**: `.github/` больше не весь — только `^\.github/workflows/fork-`. Это закрывает и «дыру `.github/`» из R02 (п.расхождений №4): правка любого upstream-workflow (`ci-server.yaml` и др.) имеет статус `M` → ловится независимо от OURS.
- `--no-renames`: переименование читается как `D+A` и не прячет правку ядра.
- `locales` оставлены в OURS как исключение: `docs/PATCHES.md` прямо говорит, что `.po` в реестр **не вносятся** — иначе гейт упирался бы в правило, которого нельзя придержаться (это единственное отступление от буквы задания, причина указана в коде).

1. **Swap 87.3% (8042/9216 МБ) — выше порога F.** Сам `--lite`-стек держит swap высоким (Docker VM 8 ГБ + node). Следствие: тяжёлые команды заблокированы уже сейчас, не только «профилактически».

Содержимое деревьев не менялось, менялась только история — поэтому и пустой diff, и 36472 = 36472.

4. **D1-архив не покрывал `.ecc`** — архивировал только `.claude` (387). `.ecc` (память: project/runbooks, team) лежит в `.git/info/exclude` и игнорируется, поэтому `ls-files -o -i` его не вернул. Добавлен отдельный архив `ecc-memory-2026-10-09.tgz` (2 файла).
5. **Все хэши коммитов переписаны `filter-branch`.** Ссылки на `b4dd7f1327`, `49e14717df`, `1e7be2241c`, `de833f1e25` и др. в `R01`, `R02`, `CONTEXT-LOG` теперь указывают на несуществующие в ветке объекты (они живут только в backup-ветках). Это ожидаемо после C2; новые хэши — в разделе C2 выше.
