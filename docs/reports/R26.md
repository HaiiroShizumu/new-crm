# R26 — H-11: документ для оператора по карточке приложения Б24 (2026-10-13)

Вход: `docs/TODO-docflow.md` §H-11. Новый файл: `docs/ops/bitrix-app.md`.

## Сделано

Памятка оператору на 7 разделов; всё взято из ADR-015 и кода `smb-bitrix`, выдуманного нет:

1. **Что понадобится заранее** — `client_id`/`client_secret` тиражного приложения; без них
   `503 NOT_CONFIGURED`.
2. **Адреса в карточке** (таблица): `https://<корень>/webhooks/smb-bitrix/{app,install,event}`,
   подписывать `ONAPPINSTALL` и `ONAPPUNINSTALL`; что делает каждый адрес — по
   `smb-bitrix.controller.ts` (`install` требует администратора портала, `app` отвечает `303` на
   `…/verify?loginToken=…&returnToPath=/docflow`, `event` сохраняет/сверяет `application_token`,
   прочие события не обрабатываются). Префикс — `SMB_BITRIX_ROUTE_PREFIX` (`ApiPath.Webhooks`).
3. **Права**: `user`; установку запускает администратор портала (`user.admin`, код `ADMIN_REQUIRED`),
   сотрудник без `email` не войдёт.
4. **Переменные на сервере** — три имени из H-10, обязательность пары
   (`parse-smb-env.util.ts:41-52,82-85`), как пересоздать контейнеры тем же вызовом, что
   `smb/deploy/bin/deploy.sh:47-48`.
5. **Установка и статус портала** — `PENDING → ACTIVE → UNINSTALLED`, `PENDING` ставится
   миграцией `bitrix/0001` по умолчанию, без флага авто-создания компания не создаётся
   (`smb-bitrix-launch.service.ts:55-65`), пока `PENDING` открытие даёт `PORTAL_NOT_ACTIVE`,
   удаление не трогает аккаунты и привязки.
6. **Привязка портала** — команда `smb:bitrix:bind-portal --member-id … --workspace-id …`
   (задача H-13, её в дереве ещё нет — так и написано), привязка ставит `ACTIVE`.
7. **Проверка адресов** — `403` без refresh-токена, `503` без переменных (по R14), дальше только
   с живым порталом.

В конце — ссылки: ADR-015, ADR-008 (шлюз), задачи `TODO-docflow.md` (H-10, H-13, V-4).
