## 3. Адаптации под v2.45.6 (без них не собиралось бы)

1. **Удалены режимы Messenger и Document management** (8 файлов): `useActiveNavigationDrawerMode`, `useSwitchNavigationDrawerMode`, `useNavigationDrawerModes`, `useMenuSearchEntries`, `useMobileNavigationBarItems`, `getNavigationDrawerHomeDestination`, `MainNavigationDrawerContent`, `AppNavigationDrawer` — плюс `SmbTopBarContent` (пикер коллег). Причина: членов `NAVIGATION_DRAWER_TABS.MESSENGER/DOC_MANAGEMENT` и `AppPath.Messenger/DocManagement*` в v2.45.6 нет. Разделы вернутся как **пункты модулей из реестра** (C-блок, D-блок) — ровно то, чего требует U-2 («из реестра, а не из условий в коде»).
2. **`ThemeContext` → `useTheme()`** (3 файла: `TwoLevelNavigationRail`, `MainNavigationDrawerModeSwitcher`, `NavigationDrawerModesOnlyContent`) — `ThemeContext` из `twenty-ui/theme` больше не экспортируется.
3. **`MobileNavigationBar`** — взята реализация v2.45.6 (единственный файл из базы, а не из старого билда): версия старого билда использует удалённый `twenty-ui/components.NavigationBar` (40+37 строк + SCSS-модули в старом `twenty-ui`, конверсия в linaria — непропорционально). Состав пунктов по-прежнему наш (`useMobileNavigationBarItems`).
4. **`SmbShellLayout`** (бывший `DefaultLayout` старого билда): убрана embed-ветка doc-management (`useDocManagementEmbedMode`, `DocManagementEmbedHeader`), экспорт переименован `DefaultLayout` → `SmbShellLayout`.
5. **Удалён `TopMessengerColleaguePicker.tsx`** (после п.1 стал сиротой и зависел от `AppPath.Messenger`).
6. **Правки house-правилами oxlint в скопированном коде** (как R04 §3.4): имена переменных/сеттеров под `twenty(matching-state-variable)` (3 файла), `useRef` вместо состояния → зачёт `entries` в deps (`useRecordRecentMenuNavigationTransition`), сортировка CSS-свойств (`TwoLevelNavigationRail`), жёсткий цвет `rgba(0,0,0,0.18)` → `var(--smb-scrim)` (переменная объявлена в `smb-skin/styles/smb-skin.css:102,124`).
7. **`ui-preferences` не дублируется**: вместо своих копий три файла импортируют `@/smb-ui-preferences/*` (каталог задачи U-3). Иначе два экземпляра атома `layoutModeState` с одним ключом `uiPreferences.layoutMode` расходились бы в рамках сессии (настройка раскладки из UI не дошла бы до оболочки).
8. **Не перенесены осознанно:** `__tests__`/`__stories__` navigation (14 файлов — написаны под v2.42.6 и штатные внутренности базы), `SmbNavigationModePillTabs` (сирота, 0 потребителей), `SmbAppShellSkeletonLoader` (подключается только правкой `loading/components/UserOrMetadataLoader.tsx` — это был бы **второй** шов ядра сверх P-015).

## 5. RV-1 — кэш `lazy`

`createSmbModuleRouteObjects.tsx:15-33` — кэш `Map<key+path → компонент>` уровня модуля, `lazy(route.loader)` вызывается один раз на ключ.

Сколько раз вызывается `createWorkspaceRouteObjects` (условие RV-1): **больше одного** —
`WorkspaceApp.tsx:8` подписан на `currentUserState`, `WorkspaceApp.tsx:17` вызывает
`useCreateWorkspaceAppRouter` в рендере → `useCreateWorkspaceAppRouter.tsx:110` →
`createWorkspaceRouteObjects.tsx:73` (`...createSmbModuleRouteObjects()`). Любой ре-рендер
`WorkspaceApp` (смена сессии/юзера/флага) пересобирал роутер и создавал новые `lazy`-компоненты →
React размонтировал бы открытую страницу модуля.

Тест `__tests__/createSmbModuleRouteObjects.test.ts` (3 кейса): стабильность ссылки страницы между
вызовами, один компонент на `key+path`, разные компоненты для разных ключей на одном пути.

## 6. RV-2 (фронт) — «включён = App установлен» + состояние приложения

- `types/SmbApplicationLifecycle.ts` — `loading | idle | installing | install-failed | uninstalling | unknown`.
- `utils/getSmbApplicationLifecycle.ts` — чистая функция из статусов джоб + `SMB_BLOCKED_APPLICATION_LIFECYCLES`.
- `states/smbApplicationLifecycleState.ts` — `Record<universalIdentifier, lifecycle>`.
- `components/SmbApplicationLifecycleLoaders.tsx` — на каждый App реестра по два запроса
  (`FindInstallApplicationJobStatus`, `FindUninstallApplicationJobStatus`); оба закрыты
  `SettingsPermissionGuard(APPLICATIONS)`, поэтому без флага пишется `unknown` (решает список App).
- `utils/filterEnabledSmbModules.ts` — третий аргумент: `installing | install-failed | uninstalling`
  **выключают** модуль, даже если запись App уже в списке; `unknown`/отсутствие ключа — не выключает.
- Монтирование: одна строка `<SmbApplicationLifecycleLoaders />` в `SmbShellLayout` (наш каталог).

## Расхождения с R04 / ADR

1. **ADR-009 п.4 «P-015 = одна строка» не выдержана**: фактически **2 строки** (импорт + элемент),
   как P-014 в M-3 (там «одна строка» стала тремя — прецедент записан в R05).
2. **R04 §3.1 считал только пути** (14 дырок); для оболочки того же уровня проверка имён и членов
   перечислений даёт ещё **1 экспорт + 4 члена** — методику R04 стоит расширить (иначе `AppPath.Messenger`
   «резолвится» как существующий импорт).
3. **R04 §9 «13 пропущенных файлов»**: из них для U-2 нужны были `SmbTopBarContent` (восстановлен)
   и форковая navigation (перенесена); `SmbNavigationModePillTabs` и `SmbAppShellSkeletonLoader` остаются
   неперенесёнными (второй требует нового шва ядра).
4. **Один файл взят из базы, а не из старого билда** — `MobileNavigationBar` (причина: удалённый
   `twenty-ui/components.NavigationBar`).
5. **Режимы MESSENGER/DOC_MANAGEMENT удалены**, а не «перенесены»: их нет в ядре v2.45.6;
   разделы возвращаются через реестр модулей (C/D-блоки).
6. **`ui-preferences` не мой**: вместо локальных копий — импорты `@/smb-ui-preferences` (U-3,
   параллельный поток). Это сознательное отклонение от «копия без правок» ради единственного
   экземпляра атома `layoutModeState`.

## Опасения

1. **`NODE_ENV=development` в контейнере** — jest падает на любой импорт linaria
   («Using the "styled" tag in runtime is not supported», `node_modules/@linaria/react/dist/index.js:87`
   бросает, только если `NODE_ENV !== 'test'`). Координатору: запускать тесты с `NODE_ENV=test`,
   иначе воспроизводятся ложные падения и у штатных тестов (`MobileNavigationBar.test.tsx` падает
   и без моих правок).
2. **Typecheck не прогонялся** (запрещён): риск дрейфа пропсов в 33 изменённых upstream-компонентах
   из diff — прежде всего `NavigationDrawerItem`, `NavigationDrawerSection(Title)`,
   `SettingsNavigationDrawerItems`, `NavigationMenuItemIcon`, `NavigationDrawer`.
3. **Жёсткая зависимость `smb-shell` → `smb-ui-preferences`** (U-3, параллельный поток, ещё не
   закоммичен): 3 импорта (`useNavigationChromeLayout`, `getNavigationChromeLayout`,
   `MainNavigationDrawerModeSwitcher`). Если каталог U-3 не зафиксируют — typecheck сломается.
4. **Переводы пунктов меню**: `i18n._(labelKey)` вернёт сам ключ, пока U-6 не положит каталог (UI-строки
   будут вида `absences.title`).
5. **Поведение не проверено в браузере**: реестр сейчас пуст (0 модулей), `SmbModuleNavigationItems`
   возвращает `null`; двухуровневый рельс, режимы раскладки и палитра поиска работают «по коду».
6. **Штатный `DefaultLayout` остался** в `testing/decorators/PageDecorator.tsx` — осознанно (тесты
   штатных страниц), но это значит, что тесты оболочки его не используют.
