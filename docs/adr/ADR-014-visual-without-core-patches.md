# ADR-014: Визуал через токены и штатные хуки upstream, без правок компонентов ядра

**Статус:** Предложено (утверждение за владельцем); п.1–4 реализованы 2026-10-12
**Дата:** 2026-10-12
**Основание:** вход владельца 2026-10-12 («перенести визуал старого билда: прозрачность, регулировки — оптимизированно, без костылей, сохраняя архитектуру; штатный интерфейс Twenty не нужен»), отчёт `docs/reports/U8-visual-glass.md`
**Связанные:** [ADR-005](ADR-005-visual-layer.md) (токены), [ADR-007](ADR-007-unified-stitch.md) (швы), [ADR-009](ADR-009-module-contract.md) п.5 (граница «новый интерфейс»)

---

## Контекст

Скин старого билда (v2.42.6) держался на правках ~25 файлов ядра: атрибуты `data-smb-*` в таблицах,
карточках, шапках страниц, порталы заголовка в `PageHeader`/`PageCardHeader`/`TopBar`. После переноса
82 файлов скина (R04) эти правки не переносились, поэтому селекторы скина ни с чем не совпадали:
панели были непрозрачными, настройки оформления не были подключены, обои и шрифт не грузились.

Повторять 25 правок нельзя: каталоги `object-record`, `ui/layout`, `navigation` — самые изменчивые в
upstream, каждая правка — будущий конфликт слияния (путь A, O-3).

## Варианты

- **A. Вернуть правки ядра** (как в старом билде): полный контроль, ~25 строк в `PATCHES.md` в зонах высокого churn.
- **B. Только CSS поверх сгенерированных классов Linaria**: 0 правок, но имена классов меняются при каждой сборке — не работает.
- **C. Токены по областям + штатные хуки upstream + минимум швов для перестановки элементов.**

## Решение — вариант C

1. **Стекло — токенами.** Области `[data-page-surface]`, `[data-side-panel]` (оба атрибута рендерит сам
   upstream) и наш `[data-smb-rail-wrap]` переобъявляют `--t-background-*` и `--t-font-color-*`.
   Компоненты ядра не знают о скине. Там, где цвет зашит инлайном из JS-темы (ячейки таблицы, колонки
   и карточки канбана), используются стабильные хуки upstream: id `record-table-*`, `record-board-*`,
   `data-record-board-column-id`, классы `table-cell` / `header-cell` / `footer-cell`.
   Единственный структурный селектор — карточка страницы `[data-page-surface='main'] > * > *`;
   при смене вёрстки upstream страница станет непрозрачной, но не сломается.
2. **Перестановка элементов — через штатный контекст.** `PageCardHeader` уже умеет порталить заголовок
   и действия в `WorkspaceSurfaceHeaderPortalContext` (так работает боковая панель). Оболочка форка
   поставляет в этот контекст свои хосты (`SmbChromeHeaderPortalProvider`): заголовок — в верхнюю
   строку приложения, действия — в строку представлений (`SmbChromeActionsSlot`), а где её нет — в
   верхнюю строку. Швы: одно условие в `PageCardHeader` (P-025) и замена двух узлов в `ViewBar` (P-026).
3. **Заглушка загрузки** — файл `UserOrMetadataLoader.tsx` целиком заменён реэкспортом нашей оболочки-скелета
   (P-024). Цвет всех скелетонов (в том числе штатных) задаёт CSS через хук библиотеки
   `--custom-highlight-background` и токен текста текущей области.
4. **Читаемость стекла — конструкцией, а не перекраской текста.** Ползунок прозрачности отображается в
   диапазон `[порог, 1]` (тёмная тема 0,38; светлая 0,5), фон под стеклом приводится к тону поверхности
   (`backdrop-filter: brightness`). Подбор цвета текста по яркости обоев (`pickSmbProgressiveGlassText`)
   удалён: на светлых обоях он давал серый текст на сером стекле.
5. **Шрифт** Manrope лежит в `smb-brand/fonts/` (latin + cyrillic, 10 файлов woff2, OFL) — без новой
   зависимости в `package.json` и без `yarn install`.

## Последствия

- Правок ядра под визуал — 5 строк реестра (P-024…P-028) вместо ~25 файлов.
- Удалены мёртвые правила CSS, завязанные на `data-smb-*` в компонентах ядра (особые тела карточек
  сделок и задач, список папок). Компоненты `smb-skin/records/*` остаются в каталоге, но не подключены:
  их возврат — отдельное решение (нужен шов в `RecordBoardCard`).
- Обновление upstream проверяется глазами по трём хукам: `data-page-surface`, id `record-table-*` /
  `record-board-*`, контекст портала шапки.

## Что нужно проверить

1. Визуальная регрессия (Playwright, 320/768/1024/1440, обе темы) — NOT RUN, нужна VM.
2. Каталоги переводов: новые строки настроек оформления и вкладок не извлечены в `ru-RU.po`
   (отображаются по-английски) — отдельная задача «переводы».
