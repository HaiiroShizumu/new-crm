# ADR-012: Русский язык по умолчанию для новых компаний

**Статус:** применяется (основание — гейт объёма цикла 2026-10-12, TODO U-6; ADR создан по правилу форка «правка ядра больше одной строки — плюс ADR», `CLAUDE.md` раздел «Форк»)
**Дата:** 2026-10-12
**Основание:** TODO U-6; вход владельца (продукт для российского МСБ)
**Связанные:** [ADR-005](ADR-005-visual-layer.md) (скин), TODO U-7 (бренд)

---

## Контекст

Twenty выбирает язык по умолчанию из браузера (`initialI18nActivate`) и пишет локаль нового
участника как `'en'` при отсутствии значения (`sign-in-up.service.ts`). Для нового продукта
интерфейс по умолчанию должен быть русским, при этом существующие компании менять нельзя.

Факты на базе `v2.45.6`:

- `ru-RU.po` есть и в серверных (`i18n/locales/ru-RU.po`), и во фронтовых каталогах переводов —
  русский входит в штатный набор локалей, отдельный каталог переводов не нужен.
- Следствие локали по умолчанию: `useAuth` шлёт `i18n.locale` → `user-workspace.service.ts:203`
  → `workspaceMember.locale` → `useLoadCurrentUser.ts:106`. Цепочку подтвердил перенос U-6.

## Решение

Две точки, обе — правки ядра с записями в `docs/PATCHES.md`:

| Точка | Файл | Что меняем | Запись |
|---|---|---|---|
| инициализация фронта | `packages/twenty-front/src/utils/i18n/initialI18nActivate.ts` | стартовая локаль `APP_LOCALES['ru-RU']` вместо `APP_LOCALES.en`, детект языка браузера отключён | **P-021** |
| новый участник | `packages/twenty-server/src/engine/core-modules/auth/services/sign-in-up.service.ts:126-127` | `?? 'ru-RU'` вместо `?? 'en'` | **P-022** |

Правила:

- **Только новые компании и новые участники.** Существующие `workspaceMember.locale` не трогаются:
  у уже работающих пользователей язык остаётся прежним (правка значений данных — отдельная задача).
- **Каталоги переводов не коммитятся** вне задач про переводы (`CLAUDE.md`, раздел «Форк»): `locales/*.po`
  и `locales/generated/*` остаются штатными от upstream, мы на них не влияем.
- Детект браузера отключён осознанно: он вернул бы `en` у англоязычного браузера внутри русской
  компании. Смена языка вручную — штатной настройкой профиля, она приоритетна.

## Последствия

- **Плюсы:** продукт выглядит русским «из коробки» без настройки; штатные переводы upstream
  используются как есть; две правки, обе в реестре.
- **Минусы:** пока переводы не обновлены, часть строк остаётся английскими (покрытие `ru-RU.po`
  от upstream); письма и серверные сообщения, использующие локаль из БД, тоже становятся русскими
  для новых участников — это ожидаемо, но надо учесть в шаблонах писем.
- **Процессно:** выбор языка для **существующих** компаний — отдельная задача (миграция данных),
  в этот ADR не входит.

## Что нужно проверить (NOT RUN)

1. Новая компания: экран регистрации и оболочка на русском без ручной смены.
2. Письма новому участнику приходят на русском (если локаль берётся из пользователя до создания).
3. Смена языка в профиле переключает интерфейс обратно (детект браузера выключен — не должен
   возвращать `en` при следующем входе).
