# Модуль «Структура компании» (`smb-org-structure`)

Дерево отделов, должность и непосредственный руководитель у сотрудника, страница «Структура».
Ключ модуля — `org-structure`; App — `packages/twenty-apps/smb/org-structure/`.

## Что где

| Часть | Файлы |
|---|---|
| App (G-1) | объект `department` (`src/objects/department.object.ts`); связи `parentDepartment` ↔ `childDepartments`, `head` ↔ `headedDepartments`; на штатном участнике — `department` ↔ `members`, `manager` ↔ `subordinates`, текстовое поле `jobTitle`; вью «Все отделы», пункт меню. Идентификаторы — `src/universal-identifiers.ts` |
| Страница (G-2) | `packages/twenty-front/src/modules/smb-org-structure/` — дерево отделов с сотрудниками, перенос сотрудника перетаскиванием (обновляет `workspaceMember.departmentId` штатным `useUpdateOneRecord`), карточка сотрудника |
| Сервис «кто руководитель» (G-3) | `SmbOrgStructureService` (`smb-org-structure/services/`), экспортируется модулем; логика — `OrgStructureResolver` |
| Запрет цикла (G-4) | PRE-хуки `department.updateOne` / `department.updateMany` |

## Правила руководителя (G-3)

`findMemberManagerId(memberId)`:

1. явный `manager` участника (если это не он сам);
2. иначе `head` его отдела;
3. иначе `head` ближайшего вышестоящего отдела, где руководитель назначен;
4. руководитель отдела сам себе не начальник — для него поиск идёт с отдела выше.

`findMemberManagerChain` — все начальники снизу вверх, `findDepartmentHeadId` — руководитель отдела с наследованием
сверху. Цикл в уже записанных данных обрывает обход (предел глубины — 64), а не зацикливает.

Потребители: процессы (шаг «Задание», исполнитель «руководитель запустившего / отдела», P-2) и отсутствия (A-3, A-5).

## Запрет цикла (G-4)

`department.updateOne`: смена `parentDepartmentId` отклоняется, если новый родитель — сам отдел или его потомок.
`department.updateMany`: массовая смена родителя запрещена (проверка поштучно невозможна для фильтра) — родителя
меняют по одному. Создание отдела цикла породить не может.

## Структура не ограничивает видимость записей (G-5)

**Не обещать клиентам**: «руководитель видит только записи подчинённых» этим модулем не реализуется.
Для такого нужны построчные права (row-level), а они в Twenty — Enterprise-функция, файлы которой использовать
нельзя (`TODO.md`, O-10). Отдел и руководитель — **справочные данные и основа маршрутизации** (кому назначить
задание, кто согласует, кто в отпуске), а не граница доступа. Любой, у кого есть право читать объект, видит
его записи независимо от отдела (ADR-013 п.5).

## Не проверено (NOT RUN)

- Установка App на чистой компании и существование самореференсных связей `department → department`,
  `workspaceMember → workspaceMember` в SDK/метаданных — спайки **S1 / S1a**.
- Срабатывание PRE-хука по ключу `department.updateOne` для пользовательского объекта (для `task.updateOne`
  подтверждено A2) — проверить на стенде.
- Страница в браузере, перетаскивание, права на обновление `workspaceMember` ролью пользователя.
- Jest-тесты (серверные и фронтовые) в контейнере; `tsc`, `oxlint`.
